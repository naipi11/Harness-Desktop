# dsh-credentials-platform

[English](README.md) | 中文

仅限 Runtime 的[凭据](../credentials/README.md)提供方：harness home 只持久化不透明引用。Windows 默认使用凭据管理器并仅在本机持久化，手动值优先于启动器冻结的环境值。其他平台默认使用只读环境适配器，除非宿主提供替代实现。

## 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `harnessHome` | 必需 | 引用元数据文档所在的绝对 harness home。 |
| `adapter` | 按操作系统选择 | 可选的替代实现，覆盖 Windows 凭据管理器或只读环境后备。 |

## 元数据文档

`$HARNESS_HOME/.credential-references.json` 记录哪些引用已配置：

```json
{
  "version": 1,
  "references": [
    "DEEPSEEK_API_KEY"
  ]
}
```

提供方会在就绪前加载并验证这份严格的 version-1 文档；文档缺失表示没有已记录的引用。文档仅包含 `version` 和一个已排序、无重复的 `references` 数组。它只持有不透明的引用名称——机密值绝不会出现在其中、命令行、日志或诊断信息里。写入通过 [`dsh-atomic-write`](../../util/atomic-write/README.md) 在仅所有者（`0700`）目录下以 `0600` 模式原子持久化。

## 平台与环境适配器

Windows 把 UTF-8 值保存为通用凭据，使用规范化 Harness home 与引用划分命名空间，并设置 `CRED_PERSIST_LOCAL_MACHINE`。值在重启应用后仍存在，但不会漫游到另一台电脑。Windows API 将单个值限制为 2,560 字节。`unset` 删除系统存储中的覆盖值，可能重新启用环境值。只有系统条目确实缺失时才使用后备；访问失败会返回不含值的错误。`describe()` 单独报告存储写入能力，因此 Windows 上当前来自环境的值仍可编辑。

环境后备通过 [launch-environment](../../util/launch-environment/README.md) 读取启动器冻结的进程层，空值视为缺失。没有系统适配器的平台会拒绝 `set` 和 `unset`，`describe()` 报告 `writable: false`。

## 安全边界

值绝不进入本包写入的文件。Windows 在当前登录用户账号下保护凭据库；以同一用户运行的其他进程可能访问它，因此它不是隔离同用户代码的沙箱。可变缓冲区在使用后清零，但 JavaScript 字符串无法可靠清零。浏览器仅接收配置状态、来源和可写能力，不接收已保存的值。

向同一个提供方实例发出的变更会串行执行。提供方先原子持久化候选引用元数据，再调用适配器，因此元数据写入失败时适配器保持不变。适配器变更在拒绝时必须保持其持久值不变；适配器拒绝后，提供方会恢复先前元数据并报告适配器失败，如果元数据回滚也失败则一并报告。两次提交都成功后，提供方才发布更新。不支持让多个提供方实例或进程并发共用同一个 `HARNESS_HOME`，因为它们各自加载独立的元数据快照，并发写入可能丢失某项引用更新。

## 模型体验

间接影响：通过为各自模型调用解析凭据引用的提供方适配器。

#### KV Cache 影响

无；该提供方既不组装也不改变模型可见的请求内容。

## 已知限制与暂缓事项

- **环境变化不可见** — 快照在启动时冻结；Windows 用户可保存手动值覆盖它，无需重启。
- **非 Windows 默认只读** — 这些宿主需要提供可写适配器。
- **无热重载** — 不监听元数据文档的外部更改；读取始终经过适配器，因此值在每次请求时保持最新。
