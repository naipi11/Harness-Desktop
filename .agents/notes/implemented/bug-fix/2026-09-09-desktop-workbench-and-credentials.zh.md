# Agent Note: Windows 可写凭据与直接执行的工作台命令

Status: implemented

[English](2026-09-09-desktop-workbench-and-credentials.md) | 中文

## 问题

生产凭据提供方仅能读取环境变量时，桌面凭据表单无法接受修改。工作区文件面板不能复用原生选择器组合明确拒绝的目录选择器 API。把输入发送给 `session.prompt` 的终端控件不是本地命令控制台，硬编码的外壳文案也不会跟随所选语言。

## 决策

Windows 通过已有 Koffi 依赖使用凭据管理器，显式选择仅本机持久化，并使用独立命名空间的通用条目。手动值优先于冻结的启动环境，删除覆盖值可能恢复环境后备。渲染器仅接收不含值的凭据元数据，提供方错误与观察者诊断不会转发任意错误内容。[提供方 README](../../../../packages/credentials/credentials-platform/README.md) 定义存储限制。

Runtime 拥有使用 cookie 认证的工作台操作：有界读取已登记工作区的后代，以及按所有者隔离的持久命令 shell。命令直接发送到清除了凭据环境变量的子进程，不经过模型 Turn。Windows 使用管道 PowerShell，因为现有 PTY 进程检查器没有 Windows 实现。按行输入的控制台明确不支持全屏和交互式程序，关闭控制台会终止其进程树。[Runtime README](../../../../packages/host/local-runtime/README.md) 定义生命周期细节。

外壳跟随共享语言服务，收起工具面板时保留对话，并显示文件和终端错误，而不把失败表现为空的成功状态。所选工作区变化后，外壳拒绝迟到的终端启动结果。

## 考虑过的替代方案

**只启用密码输入框而不改变提供方。** 拒绝，因为每次写入仍然失败。

**在应用明文文件中保存 API 密钥。** 拒绝，因为现有适配器允许使用系统存储，无需增加保存秘密的文件。

**原样复用 PTY 服务。** 此次 Windows 修复不采用，因为它的进程检查器拒绝 Windows。完整 ConPTY 实现属于独立改动，命令控制台明确说明限制，不宣传不支持的交互能力。

**把终端输入作为模型提示词。** 拒绝，因为用户期望确定的本地执行，不依赖 API 凭据或模型解释。

## 后果

每个 Harness home 仍只有一个持久化所有者。Windows 凭据在重启应用后保留，但同用户进程可访问它，不构成针对该用户的沙箱。控制台输出有界且仅存于内存，不成为模型可见的文本记录。原生存储往返、真实 shell 命令、cookie 认证和构建版 Dashboard 浏览器演练分别提供证据，均不证明模型提供方或生产更新器可用。
