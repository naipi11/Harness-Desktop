# Web 后台启动设计

[English](2026-08-14-web-daemon-design.md) | 中文

## 范围

`dsh web` 增加可选的本地 Web UI 脱离终端运行方式。前台调用和现有全部 Web 选项保持原有行为。

## 命令行

`dsh web --daemon` 与 `dsh web --background` 是等价别名。任一标记都可与现有 Web 选项一起使用，同时传入两个标记仍只启动一个子进程。这些标记仅对 Web profile 有效。

`dsh web --help` 优先于脱离终端执行。调用同时包含 `--help` 与任一别名时只输出 Web 帮助，不创建子进程。

## 进程生命周期

前台 CLI 进程移除后台执行标记，以其余原始参数重新执行同一 Node 入口，并在子进程创建后退出。子进程沿用未改变的 Web profile 启动路径，因此保留现有 host、port、信任、就绪和信号清理行为。

父进程启动跨平台的脱离终端子进程，关闭标准输入，将标准输出和标准错误重定向到 `$DSH_HOME/logs/` 下的一个日志文件，释放进程引用，并输出子进程 PID 与日志路径。父进程成功只表示子进程已创建，不表示 Web 服务已完成启动。

## 失败与运维

创建日志目录、打开日志文件或启动子进程失败时，CLI 报告错误并以非零状态退出。普通 Web 启动期间发生的失败保留在子进程日志中，并使用现有 Web 失败行为。该功能不增加服务管理命令、登录时启动、非回环监听或就绪轮询。

## 实现与测试

CLI 负责脱离终端进程编排，因为该操作必须发生在 Web profile 挂载之前。一个聚焦的辅助模块接收原始 argv，识别并移除两个别名，构造子进程启动方式，并通过依赖注入支持单元测试。

测试覆盖两个别名、重复别名、参数保留、帮助优先级、日志或启动设置失败，以及脱离终端子进程的启动选项。一个已构建 CLI 集成测试会启动 Web 子进程，在父进程退出后观察响应，并通过现有进程信号路径终止该子进程。
